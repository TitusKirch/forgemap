---
title: 'Manage a repository collection'
description: 'Clone, locate, inspect, and maintain repositories without losing the layout that identifies them.'
---

Treat the configured collection as the source for navigation rather than a list
of directories to remember. A slug identifies a repository consistently across
clone, lookup, and maintenance commands.

## Add or adopt repositories

Clone a remote when it is not present yet. When the collection already exists
on disk, import it first so forgemap can reconcile the folders with their
remotes and derive the matching layout. Import reports before changing paths;
use its fix mode only when the report identifies a layout or remote that should
be corrected.

## Locate the checkout you need

Use an exact slug when the owner or group is known. For a remembered fragment,
the listing and locator commands use the same fuzzy matching model, so a unique
match can take you from a term to a path or an interactive selection without
relearning the collection's tree.

## Inspect before changing many repositories

Status reports the local state of the collection, and sync refreshes remotes in
parallel. Narrow either workflow to the owners or forges relevant to the task
instead of treating every checkout as equally urgent.

## Preserve work when cleaning up

Cleanup and deletion are intentionally guarded by local state and remote
availability. Read their report before confirming a removal: a checkout with
local work, a stash, or no reachable remote is evidence that the on-disk copy
may still matter.

For exact flags and output formats, see the
[command reference in the README](https://github.com/TitusKirch/forgemap#all-commands).
